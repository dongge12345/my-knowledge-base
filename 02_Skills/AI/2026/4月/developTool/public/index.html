Chrome DevTools 实战训练场

把“只会看 Network 和 console.log”补成一套能说、能查、能修的排查方法。

这个练习项目专门围绕两类高频面试题设计：首屏加载慢怎么查，内存泄漏怎么查。你会先认识工具和指标，再进入可复现场景做完整排查。

先学工具与指标 直接进首屏慢场景

你会练到什么

  • Network 怎么判断资源阻塞和请求瀑布
  • Performance 怎么看主线程长任务和首屏指标
  • Memory 怎么用快照和时间线抓泄漏
  • Lighthouse 和 Coverage 在排查里分别扮演什么角色

关键指标

推荐顺序

  1. 先记住每个面板解决什么问题
  2. 再练一次问题版页面的完整排查
  3. 最后切换到优化版，观察差异并复述原因
学习区

工具与指标速查

认识 Network、Performance、Memory、Lighthouse、Coverage，以及 FP / FCP / LCP / TBT / TTI。

 实战区

首屏加载慢

问题版会制造主线程阻塞和同步渲染压力，适合用 Performance、Coverage 练习定位。

 对照区

首屏优化版

把同步阻塞拆散，并把次要内容延后渲染，你可以直接和问题版对比 FCP / LCP 的差别。

 实战区

内存泄漏

反复挂载和卸载组件，观察事件监听、定时器和大对象引用没有释放时会发生什么。

 对照区

内存修复版

同样的操作流程，加入清理逻辑后，重新观察 Heap Snapshot 和时间线内存变化。

先记住一句排查顺序

首屏问题优先从 Network 看资源，再到 Performance 看主线程；内存问题优先从 Memory 看对象是否被释放，再回代码确认是哪条引用链没断。
