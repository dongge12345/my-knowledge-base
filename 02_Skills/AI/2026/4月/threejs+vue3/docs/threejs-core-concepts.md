# Three.js 核心概念速读

这份文档的目标不是把 Three.js 讲成一本书，而是让你先建立“足够正确、足够实用”的 3D 直觉。

## 1. Three.js 到底是什么

Three.js 不是浏览器里的新渲染引擎，而是对 `WebGL` 的上层封装。

你可以先这样理解：

- `WebGL` 更接近底层 GPU 接口
- `Three.js` 帮你把场景、相机、网格、材质、光照、控制器这些常见能力封装好了

所以 Three.js 的价值，不是替代浏览器，而是让前端工程师能以更高抽象层搭建 3D 页面。

## 2. 先建立一个最重要的公式

一个 Three.js 页面最核心的链路是：

`Scene + Camera + Renderer + Mesh + Light + Animation Loop`

可以先把它翻译成前端人的语言：

- `Scene`：整张 3D 页面里的“根容器”
- `Camera`：你从哪里看场景
- `Renderer`：负责把 3D 世界画到 canvas 上
- `Mesh`：真正可见的 3D 物体
- `Light`：让物体看起来有体积和层次
- `Animation Loop`：持续更新和渲染场景

## 3. 场景树为什么重要

Three.js 是典型的场景图结构。

这意味着：

- 一个物体可以有子物体
- 子物体会继承父物体的位置、旋转、缩放
- 复杂模型和复杂设备通常是由多个部件组成的

你可以把它理解成 DOM 树在 3D 世界里的版本。

这个项目里的每个设备就是一个 `Group`，它下面有底座、机械臂、探头、屏幕。这样做的好处是：

- 可以整体移动设备
- 也可以单独控制机械臂动画
- 点击子部件时还能向上找到整台设备

## 4. Mesh 是什么

一个可见物体通常由三部分组成：

- `Geometry`：形状
- `Material`：表面外观
- `Mesh`：把形状和材质组合起来的可见对象

比如：

- 盒子形状 `BoxGeometry`
- 金属表面 `MeshStandardMaterial`
- 最终组合成一个 `Mesh`

## 5. 相机是什么

前端里最常用的是 `PerspectiveCamera`。

它更接近人的视角，会有“近大远小”的透视效果。

你可以把它理解成：

- 场景是真的 3D
- 页面上看到的内容是“相机拍到的画面”

所以很多 3D 页面问题，本质上不是模型没了，而是：

- 相机没对准
- 近裁剪面或远裁剪面不合适
- 控制器 target 不合理

## 6. 为什么需要光照

很多初学者会问：我已经有颜色了，为什么还要光照？

因为没有光照，很多材质看不出体积感和空间层次。

最常见组合：

- 环境光：负责整体基础亮度
- 方向光：模拟太阳光或主光源，帮助塑形

如果你未来接触更真实的效果，还会继续看到：

- 点光源
- 聚光灯
- HDR 环境贴图
- 阴影

## 7. 动画循环为什么是 Three.js 的核心

普通网页很多内容是静态的，但 3D 场景通常不是。

这些东西都需要在每一帧更新：

- 相机控制器阻尼
- 物体动画
- 粒子或特效
- 用户交互后的反馈

所以你会看到典型写法：

```js
renderer.setAnimationLoop(() => {
  controls.update();
  renderer.render(scene, camera);
});
```

这就是 3D 页面持续运行的心跳。

## 8. 鼠标怎么点到 3D 物体

3D 世界不是二维 DOM，不能直接靠事件冒泡判断用户点到了谁。

Three.js 常见做法是：

1. 先把鼠标位置换算成标准化坐标
2. 从相机朝鼠标位置发出一条射线
3. 用射线和场景对象做相交检测
4. 找到最先被击中的物体

这就是 `Raycaster`。

项目里 hover 和 click 都是通过这套机制实现的。

## 9. Vue 和 Three.js 应该怎么分工

这是面试里很值得讲的一点。

建议你这样理解：

- Vue 负责界面、面板状态、生命周期、业务组织
- Three.js 负责场景对象、渲染循环、3D 交互

不要试图把 Three.js 的所有内部状态都塞进 Vue 响应式系统里。

更合理的模式是：

- 在 Vue 组件挂载时初始化 Three.js
- 把必要的控制状态暴露给 Vue
- 在组件卸载时销毁渲染器、控制器和几何材质资源

## 10. 为什么 3D 页面容易卡

3D 卡顿最常见的几个来源：

- 模型面数太高
- 纹理太大
- `draw call` 太多
- 每帧做了太多 CPU 计算
- 资源没有正确释放

你现在先重点记住一个词：

`draw call`

它可以粗理解为“一次提交给 GPU 的绘制命令”。

如果场景里有很多重复小物体，每个都单独渲染，CPU 和 GPU 的调度开销会明显增加。

## 11. 为什么 InstancedMesh 很重要

如果场景里有大量重复模型，比如货箱、货架小件、灯、树、粒子块，常见优化方式就是实例化。

它的核心思想是：

- 几何体共用
- 材质共用
- 只变化每个实例的变换矩阵

这样就能用更少的绘制调用，渲染大量重复物体。

本项目里的货箱就是实例化示例。

## 12. 你接下来该怎么学

建议顺序：

1. 先运行项目，建立视觉印象
2. 理解 `useThreeLearningScene` 里的初始化流程
3. 理解 `createLearningFactory` 如何组织场景树
4. 理解 `Raycaster`、动画循环和实例化
5. 最后再回头补 `WebGL`、矩阵、坐标系和更深层性能优化

## 13. 面试时可以怎么说

如果面试官问你对 Three.js 的理解，你可以先这样答：

Three.js 是对 WebGL 的工程化封装，它把场景、相机、网格、材质、光照、控制器这些 3D 页面高频能力抽象出来，让前端工程师能更高效地构建 Web3D 应用。我现在对它的理解重点放在三个层面：一是场景组织和交互实现，二是 Vue 这类前端框架如何和 Three.js 协作，三是模型与渲染性能优化，比如实例化、裁剪和资源管理。
