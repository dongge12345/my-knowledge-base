# CLAUDE.md

## 项目定位

这是一个用于系统学习 Claude Code 的个人实验仓库。

核心目标：

1. 掌握 Claude Code 的基础用法、进阶用法与自动化能力。
2. 理解 AI 编程、agent 协作和工程化落地的主流方法。
3. 沉淀可复用的学习资产，包括文档、脚本、skills、agents、示例项目。

当前主计划文件：

- `plan.md`：Claude Code 从 0 到 AI 工程化的 14 天学习计划

## 协作方式

- 默认使用中文输出，除非我明确要求英文命令、英文文档或英文提交内容。
- 优先给出可执行步骤，而不是只讲概念。
- 涉及命令时，先说明命令作用，再给出命令。
- 涉及新概念时，尽量提供最小可运行示例。
- 优先小步迭代，避免一次性生成过大、过杂的内容。
- 如果存在多个方案，优先给出推荐默认方案，并说明为什么推荐。

## 仓库使用规则

- 先阅读当前目录已有文档，再开始新增内容。
- 新增内容尽量围绕当前学习阶段服务，不要无关扩展。
- 如果一个任务可以沉淀为模板、脚本或清单，优先做成可复用产物。
- 不要把“学习计划”直接变成“大而全项目”，优先最小示例和最短闭环。

## 目录约定

以下目录是推荐结构；如果目录尚未存在，可按需要逐步创建：

- `plan.md`：学习主计划
- `notes/`：学习笔记、复盘、总结
- `examples/`：最小示例、命令演示、配置样例
- `skills/`：个人 skills 草稿或项目内 skill 说明
- `agents/`：个人 agent/subagent 设定草稿
- `scripts/`：自动化脚本、headless 调用脚本
- `projects/`：练习项目或阶段性 demo

## 学习任务默认输出

每次学习任务，优先输出以下内容中的 3-6 项：

1. 这次任务的目标
2. 对应的 Claude Code 能力点
3. 最小操作步骤
4. 示例命令、示例提示词或示例配置
5. 常见坑与排查方式
6. 下一步练什么
7. 是否适合沉淀为 skill、agent、hook、脚本或 CI

## Claude Code 实践原则

- 讲清楚 `claude`、`claude -c`、`claude -r`、`claude -p` 的区别和适用场景。
- 学习顺序默认遵循：`CLAUDE.md -> settings -> hooks -> skills -> agents -> MCP -> CI/SDK`。
- 解释“长执行”时，明确区分：
  - 会话内循环：`/loop`
  - 跨会话持续运行：scheduled tasks
  - 工程级稳定自动化：GitHub Actions 或 SDK
- 不把 Claude Code 描述成“万能自动开发器”，要明确它的边界、风险和验收要求。

## 产出标准

优先产出这些可复用成果：

- 速查卡
- 学习清单
- 最小示例项目
- 配置样板
- 自动化脚本
- 复盘模板

如果只是解释概念，尽量补一个最小例子，避免纯理论输出。

## 安全边界

- 未经确认，不执行破坏性操作，例如删除大量文件、覆盖现有项目、重置 git 状态。
- 未经确认，不假设外部服务已经登录可用。
- 涉及权限、自动执行、CI、MCP、hooks 时，优先说明风险边界和推荐默认配置。
- 如果信息不足，先给推荐默认方案，再说明需要用户补充的最小信息。

## 与本仓库相关的默认判断

- 当前仓库是学习实验场，不是生产仓库。
- 默认更重视“理解与复用”而不是“一次性做完”。
- 默认环境是 Windows；如遇终端或路径问题，可补充给出 WSL 方案。
- 当前阶段优先帮助用户建立稳定工作流，而不是追求复杂架构。
